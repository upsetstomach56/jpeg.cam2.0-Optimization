JPEG.CAM Menu System Options

Each direction uses one shared pattern for every page: recipes, BIONZ matrix, creative modes, photo queue, networking, support, naming, delete confirmation, and editing states. The goal is predictable D-pad behavior and identical manager screens everywhere.

Orange theme only

Shared Navigation

Every screen has the same location, page tabs, selected row, value column, and action area.

Shared Managers

Recipe manager, BIONZ matrix, and queue editor use the same list, edit, rename, duplicate, and delete controls.

Shared Naming

Naming becomes a full-screen keyboard with text box, confirm, cancel, delete, and space keys.

Shared Confirm

Delete and overwrite actions use one modal style with the same confirm/cancel placement.

A fixed left rail for top-level areas, a central row list for settings, and a right inspector for preview/actions. Best match for camera D-pad navigation.

Option A Deep Dive: One System, Many Screens

This is the expanded version of Orange Rail. The important rule is that every page uses the same shell: left rail for location, center rows for selection, right-side action/preview area when needed, full-screen naming, and one confirmation pattern.

Selected Direction
Global Shell

Every page starts with the same top bar and left rail. Recipes, creative modes, queue, network, support, and system settings no longer invent their own navigation shape.

Shared Row Contract

Rows always show label on the left and current value/status on the right. Press center to edit, left/right to adjust simple values, and back to cancel or return.

Shared Manager Contract

Recipes, BIONZ matrices, queue presets, and saved photo lists use the same actions: open, edit, rename, duplicate when useful, delete, confirm, cancel.

Option Best Use Tradeoff Android Translation
Option A Best overall for a complete camera menu overhaul. It keeps navigation obvious and manager screens identical. More visual structure than the current menu, so it needs a full `MenuController` rendering pass. Left category rail, central shared row renderer, right shared inspector/action panel.
Option B Best if you want the least disruptive change from the current tab style. Top tabs can get crowded as features grow. Reuse existing header tabs but replace every page body with shared manager rows.
Option C Best for fast action access and creative mode browsing. Cards are less efficient for long settings pages. Mode grid plus a persistent command shelf and shared row editor.
Option D Best for saved-object managers like recipes, matrices, queues, and photo libraries. Dense on a small camera display, less ideal as the global menu shell. Library list plus inspector panel for all saved item types.
